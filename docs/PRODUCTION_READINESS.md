# YCD OIL ERP - Production Readiness Runbook

## الحالة الحالية

النظام يبقى في حالة `PREOPENING` حتى اعتماد الإدارة لبدء التشغيل التجاري. بوابة التشغيل لا تُفتح لمجرد نجاح البناء البرمجي؛ يجب أن تكتمل بيانات التشغيل الفعلية واختبارات UAT.

- المنشأة: شركة وجهتك الإبداعية لخدمات السيارات.
- الفرع: الرياض - حي طويق.
- البنك الرئيسي: مصرف الراجحي.
- الحساب: 528000010006080781162.
- IBAN: SA7180000528608010781162.
- الرقم الوطني الموحد: 7038822883.
- الهوية: YCD OIL بالألوان المعتمدة #F18F21 / #F7A81D / #939497 / #BDBDBF.
- الهيكل التشغيلي الأساسي: 8 موظفين ومسؤولياتهم مثبتة في `lib/operations.ts`.

## بوابة ما قبل التشغيل

قبل تغيير الفرع إلى `LIVE` يجب أن تكون شاشة الجاهزية خالية من البنود المطلوبة، وبشكل خاص:

1. إنشاء حسابات دخول الفريق وتغيير كلمات المرور المؤقتة.
2. استيراد بيانات الموارد البشرية الفعلية للفريق: تاريخ التعيين والراتب والبدلات وبيانات التواصل وIBAN عند توفره، باستخدام قالب `/templates/ycd-preopening-employees.csv`.
3. استيراد دليل الزيوت والفلاتر والقطع بالتكلفة وسعر البيع والحد الأدنى.
4. استيراد دليل الخدمات والأسعار وتحديد أهلية كوبون الغسيل.
5. تحميل الجرد الافتتاحي الفعلي للمخزون.
6. تحميل الموردين الأساسيين.
7. نجاح اختبارات CI وبيانات ما قبل التشغيل والضوابط والهوية.
8. تنفيذ UAT على نسخة غير إنتاجية وتسجيل نتيجة كل سيناريو من شاشة `/dashboard/readiness/uat`.
9. لا تسمح بوابة GO LIVE بالانتقال إلى LIVE حتى تكون بيانات HR الأساسية مكتملة وجميع سيناريوهات UAT الإلزامية بحالة PASSED.

## UAT الإلزامي

ينفذ فريق الإدارة السيناريوهات التالية قبل الإطلاق. النظام يحفظ المنفذ والتاريخ ومرجع الدليل والملاحظات، وتبقى نتيجة UAT جزءًا من بوابة الإطلاق وليست مجرد قائمة إرشادية:

- فتح وردية بواسطة مستخدم مخول.
- استقبال سيارة وربط العميل والمركبة.
- إضافة زيت/فلتر/خدمة والتأكد من المخزون.
- إكمال بيع نقدي ثم مدى ثم تحويل.
- إصدار وطباعة الفاتورة الضريبية.
- التحقق من سجل المركبة وموعد الخدمة القادمة.
- إصدار واستخدام كوبون الغسيل مرة واحدة فقط.
- بيع آجل ثم تحصيل جزئي وكامل.
- مرتجع/استرداد مع أثره المالي والمخزني.
- طلب شراء واعتماد وأمر شراء واستلام وفاتورة مورد وسداد.
- مصروف: طلب ثم اعتماد مستقل ثم صرف.
- عهدة: طلب واعتماد وصرف وتسوية وإقفال.
- راتب: إعداد ثم اعتماد ثم صرف.
- إقفال وردية ومراجعة فروقات النقد/مدى/التحويل.
- مطابقة بنك ومراجعتها وإقفالها بدون فرق.
- إعداد الإقفال اليومي والشهري ومراجعته.
- التحقق من Audit Log لكل عملية حساسة.

## متطلبات بيئة الإنتاج

- PostgreSQL مُدار مع نسخ احتياطية تلقائية واختبار استعادة.
- `AUTH_SECRET` عشوائي طويل ولا يُحفظ في المستودع.
- حساب مدير النظام يُنشأ من متغيرات البيئة ثم تُغيّر كلمة مروره.
- HTTPS إلزامي.
- `ALLOW_PREOPENING_OPERATIONS=false` في الإنتاج.
- مراقبة `/api/health` وإطلاق تنبيه عند HTTP 503.
- تشغيل `npm run verify:production-env` على متغيرات بيئة الإنتاج قبل أول نشر وبعد أي تغيير للأسرار أو قاعدة البيانات.
- فصل قاعدة UAT عن قاعدة الإنتاج.
- عدم استخدام `prisma db push` لتغيير قاعدة الإنتاج يدويًا؛ يجب اعتماد migrations قبل أول نشر إنتاجي.

## النسخ الاحتياطي والاستعادة

قبل كل نشر إنتاجي أو تغيير قاعدة بيانات:

```bash
pg_dump --format=custom --no-owner --no-acl "$DATABASE_URL" > ycd-oil-$(date +%Y%m%d-%H%M).dump
```

اختبار الاستعادة يجب أن يتم على قاعدة منفصلة، وليس فوق قاعدة الإنتاج.

## ملاحظات إطلاق مهمة

نجاح CI يعني أن الكود يبني وأن قاعدة الاختبار والـSeed والضوابط تمر، لكنه لا يعني أن بيانات HR والأصناف والمخزون والموردين الحقيقية قد اكتملت. قرار `GO LIVE` إداري وتشغيلي بعد إكمال شاشة الجاهزية وUAT.
